Build Unns as a Native iOS App First, Not Cross-Platform

You are working on Unns, an emotionally intelligent product that aims to become a category-defining Emotional Operating System.
Because of the product’s depth, sensitivity, UX quality requirements, performance expectations, and long-term ambition, I want you to follow a native-first mobile strategy.

Strategic Direction

Do not build Unns as a cross-platform application at this stage.
Do not use Flutter, React Native, or any other cross-platform framework for the main app experience.

Instead:

Build Unns as a fully native iOS application first using Apple’s native stack and best practices.

The Android version is not part of the current execution scope.
Once the iOS product reaches a high level of maturity, quality, stability, and product-market clarity, I will explicitly request that Android development begin as a separate phase.

⸻

This is not a casual preference. It is a strategic product and engineering decision.

Unns requires:
	•	exceptional performance
	•	premium UX quality
	•	refined animations and interaction fidelity
	•	strong privacy and security implementation
	•	deep integration with native iOS capabilities
	•	better reliability for emotionally sensitive user journeys
	•	more control over app behavior and system-level experiences
	•	a polished Apple-grade product feel from day one

Because of this, I want the product built in the most robust way possible for iOS first, without compromise.
